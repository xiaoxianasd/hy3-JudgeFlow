# 过程评估方法与验证设计

> 2026-09-07：词汇规则仅作语义审查提示，离线匹配不再判定过程成立或错误。数据流程见 [评估与人工复核](EVALUATION_WORKFLOW.md)，字段和统计分母见 [三态判定协议](VERDICTS.md)。

## 1. 为什么采用混合评估

单一 LLM 审查容易受措辞影响，单一规则无法识别语义等价推导，单一测试又只能证明给定输入上的行为。因此 TraceJudge 将证据分为四层：固定可复现测试、Hypothesis 属性化差分、题目专属过程量表、Hy3 多 Agent 证据约束复核。最终报告保留各层原始证据，便于人工追溯。

## 2. 多 Agent 编排

主流程采用 `Pipeline + Supervisor`。在生成、执行、反例搜索和规则检查完成后，Supervisor 并行派发五个互相独立的 Hy3 专家：题意、算法、证明、复杂度和边界。每个专家只能审查自己的阶段，必须返回候选首错、错误类型、证据和置信度；如果本阶段只是继承早先错误，则标记根因步骤，避免重复归因。

默认 `supervisor` 模式由确定性 Python Supervisor 合并所有证据。`swarm` 模式只在专家冲突、规则冲突或发现错误时增加一轮 Hy3 仲裁，因而是有界 Swarm，不允许 Agent 无限对话。为保留基线，`single` 模式仍支持一次通用 Hy3 审查。

确定性执行证据优先：仲裁不得抹去固定测试/Hypothesis 已发现的问题；也不得把当前首错移动到更晚步骤。五个专业调用并行执行以降低延迟，但 API 用量仍分别计算。

## 3. 过程协议

Hy3 必须输出 JSON，并把推理拆为五个可引用阶段：

1. 题意与建模；
2. 算法与状态转移；
3. 正确性证明；
4. 时间/空间复杂度；
5. 边界条件。

代码是第六个隐式“实现步骤”。如果文字过程成立但代码失败，首错定位为 `len(reasoning_steps)+1`，错误类型为 `implementation_error`。

## 4. Hypothesis 验证

每道种子题都有一个满足约束的输入 strategy。每个生成输入上，参考实现与候选实现分别在新子进程中执行并差分比较。Hypothesis 的生成与 shrink 阶段会继续寻找更小失败输入；评估器从收集到的失败调用中保留结构最小的反例。固定 seed、禁用案例数据库并记录版本/预算，以便同一环境复现。

这层专门捕获：公开/隐藏固定用例恰好未覆盖的分支、重复值/空输入/符号等边界、错误贪心或错误连续性假设。

## 5. 首错与错误类型

首错必须满足“在它之前的步骤仍可成立；从该步骤开始结论失去支持”。后续由首错传播的错误不重复计为新的根因。多来源冲突时采用：可执行反例优先确认实现错误；题目专属量表提供待核查的词汇提示，不作为语义证据；Hy3 仅在置信度至少 0.65 且指出更早具体步骤时改变首错。

分类体系：

| 类别 | 判定要点 |
|---|---|
| problem_misread | 改变题目对象、方向、连续性、返回要求 |
| concept_error | 核心概念或状态定义错误 |
| algorithm_error | 转移、搜索、数据结构或不变量错误 |
| theorem_misuse | 定理/贪心使用条件不满足 |
| condition_omission | 漏掉约束、前置条件或边界 |
| calculation_error | 局部算术、下标或代数错误 |
| unjustified_jump | 关键中间结论无支持 |
| circular_reasoning | 以待证结论作为前提 |
| complexity_error | 复杂度结论与操作不符 |
| hallucination | 引用不存在的事实/定理/API |
| implementation_error | 过程可成立但程序行为不符 |
| format_error | 无法解析或缺少必需结构 |

## 6. 有效性验证

构造集对已有 gold、wrong、unsupported-correct 轨迹去重，并增加关键词堆砌/循环论证、正确过程否定错误示例的对抗变换。构造标签不作为独立人工抽检。离线运行只能验证执行与弃判；需显式启用 `--hy3-review` 才能评估 Hy3 语义定位。报告同时给出：

- 错误答案上的过程问题检出率；
- 错误答案上的首错 exact-match 定位准确率；
- 人工确认过程成立的正确答案上的误报率；
- 被标记的正确答案中，真实过程问题与误报的比例。

真实模型评测与评估器构造验收严格分开。最终参赛结果需独立人工抽检被标记的正确答案；可采用双人交叉复核，分歧样本先裁决，再保留最终记录及裁决依据。PDF 未强制规定复核人数。

检出统计使用互斥四分类：金标错误过程被判错为“检出”，被判成立为“漏检”；金标正确过程被判错为“误报”；模型复核失败、证据不足或结论缺失为“弃判”。弃判不并入漏检，报告必须同时展示。受控构造轨迹标记 `sample_origin=controlled`，Hy3自然生成轨迹标记 `sample_origin=natural`，两类结果分别汇总，禁止合并成一个效果数字。

构造集中另有两组配对反事实样本：`correct_code_wrong_proof` 仅替换证明步骤，`condition_overgeneralization` 仅替换边界步骤中的条件推广。两组均保留参考代码及其他标准步骤，每条附一个可执行反例，用于验证“最终答案正确但过程不成立”的识别能力。

## 7. 难度与能力临界点

参与临界点分析的种子题使用五维人工量表，每维 0-3 分：算法识别、状态/不变量、正确性证明、边界陷阱、复杂度约束。总分 0-6 为 easy、7-10 为 medium、11-15 为 hard。逐题分项证据保存在 `data/annotations/difficulty_calibration_seed_20260907.json`，题库中的 `difficulty_basis` 同步保留摘要。

本轮得分为：`two_sum_exists=5`、`bracket_balance=6`、`max_subarray=9`、`grid_shortest_path=10`、`coin_change=13`、`lis_length=14`，校准后仍为 easy / medium / hard 各 2 题。easy 是单一数据结构不变量；medium 需要 DP/BFS 状态和关键边界；hard 需要反贪心建模或 `O(n log n)` 不变量及更高证明负担。

正式评测固定每层等量样本，并用 Wilson 区间报告准确率。只有当相邻难度层的过程正确率出现稳定下降、区间证据足够且样本量充分时，才报告“明显下降区间”；不能根据每层 2 题的单轮结果断言模型临界点。
