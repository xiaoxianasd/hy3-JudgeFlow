# 结果与能力边界

## 当前可复现结果：评估器构造集

运行环境中的 `http://127.0.0.1:8000/v1` 尚未启动 Hy3 服务，因此本节只报告受控构造集上的**评估器有效性**，绝不作为 Hy3 模型能力成绩。机器可读明细见 `reports/fixtures_benchmark.json/jsonl/csv`。

| 指标 | 结果 |
|---|---:|
| 样本数 | 24 |
| 最终答案准确率 | 66.67% |
| 过程正确率 | 50.00% |
| 答案正确但过程不成立 | 4 / 24（16.67%） |
| 错误答案过程问题检出率 | 8 / 8（100%） |
| 首错 exact-match 定位准确率 | 8 / 8（100%） |
| 正确且过程成立样本上的误报率 | 0 / 12（0%） |
| 被标记正确答案中的真实问题比例 | 4 / 4（100%） |

构造集每个错误轨迹只注入一个已知根因，因而适合检验定位逻辑，但比真实模型输出干净。100% 定位率不意味着在开放式 Hy3 输出上也会达到同样水平。

## 分难度结果

| 难度 | 样本 | 最终答案准确率 | 过程正确率 | 正确答案但过程错误率 |
|---|---:|---:|---:|---:|
| easy | 8 | 75.0% | 75.0% | 0.0% |
| medium | 8 | 75.0% | 50.0% | 25.0% |
| hard | 8 | 50.0% | 25.0% | 25.0% |

过程正确率从 easy 到 medium 首次明显下降（75% → 50%），最终正确率则在 hard 才下降（75% → 50%）。这是构造集的预设混合比例，用于验证分析管道是否能呈现临界点；真实模型临界点必须用 `benchmark --source hy3` 的结果重算，并报告置信区间。

## 错误类型分布

| 类型 | 次数 |
|---|---:|
| 题意误读 | 5 |
| 定理/贪心误用 | 3 |
| 条件遗漏 | 2 |
| 算法错误 | 1 |

分布统计以首错根因为主，避免把同一根因传播出的后续错误重复计数。

## 典型案例

- **结果正确、过程不成立**：`coin_change` 的轨迹声称“反复选最大硬币一定最优”，但代码替换为正确 DP。固定测试和 Hypothesis 都验证代码正确，过程量表在步骤 2 定位 `theorem_misuse`，因此 `unsupported_correct=true`。
- **Hypothesis 反例**：最长递增子序列的错误实现把“子序列”当作“连续递增段”。Hypothesis 保留反例 `nums=[1,3,2,4]`，参考答案为 3，错误实现为 2。
- **实现错误**：测试中的两数之和候选实现错误地跳过零；它通过全部 6 个固定用例，Hypothesis 随后找到 `nums=[0,1,2], target=2` 一类反例。文字五步均通过量表，因此定位到第 6 个隐式实现步骤，并归类 `implementation_error`。

## 生成真实 Hy3 结果

启动/配置 Hy3 API 后执行：

```bash
tracejudge doctor
tracejudge benchmark --source hy3 --hypothesis-examples 60 --output reports/hy3_benchmark.json
```

真实报告会记录端点、模型名、每次生成/复核请求的模型与 token usage、全部分步答案、执行证据、Hypothesis 反例和难度汇总。对所有“答案正确但过程错误”样本使用 `data/annotations/human_audit_template.jsonl` 独立抽检后，才能形成正式参赛结论。
